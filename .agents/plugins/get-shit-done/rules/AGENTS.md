# Get Shit Done (GSD) Context & Spec Rules

## Core Principles
1. **Context Engineering Over Chat Bloat**: Prevent context rot by keeping working context clean. Break large goals into isolated, atomic phases.
2. **Spec-Driven Execution**: Never start writing code without an explicit, verifiable specification and step-by-step phase plan.
3. **Atomic Verification**: Every phase must end with an automated or empirical verification step before moving to the next phase.

## Phase Workflow Guidelines
- **Phase 1: Research & Discovery**: Inspect codebase, dependencies, and existing patterns without modifying files.
- **Phase 2: Planning & Spec**: Write or update clear sub-task specifications with concrete acceptance criteria.
- **Phase 3: Focused Execution**: Implement code for a single phase at a time. Keep diffs focused and minimal.
- **Phase 4: Acceptance & Verification**: Run tests, verify output, and confirm all acceptance criteria are met before marking complete.
